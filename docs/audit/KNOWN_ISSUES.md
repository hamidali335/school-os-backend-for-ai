# Known issues and remaining risks

Updated: 17 Oct 2026 (final verification). Covers `school-os-backend`,
`school-management-software-frontend` (school app) and `school-os-admin-panel`. Ordered by risk.
No known cross-tenant data exposure or privilege escalation remains (automated probe: 3,422
cross-tenant requests, 0 leaks — see FINAL_STAGING_VERIFICATION.md).

| # | Severity | Area | Issue | Mitigation now | What to do |
|---|---|---|---|---|---|
| K1 | High (until done) | Auth (platform) | No MFA for platform administrators. | **Compensating controls:** `PLATFORM_ALLOWED_IPS` (backend 404s the platform API, login included, outside the allow-list), nginx `allow/deny` for the console and `/api/v1/platform/`, password re-entry for backup download/delete, login rate limits + lockout, owner-only backups. | Keep the console LAN/VPN-only, **or** behind Cloudflare Access with the API verifying the Access token (`PLATFORM_ACCESS_*`, `docs/PLATFORM_REMOTE_ACCESS.md`), until built-in TOTP MFA exists. Never expose it with a password alone. |
| K2 | High (until done) | Deployment | The Linux deployment (systemd, nginx, TLS, ufw, permissions, reboot, log rotation) has **not been executed**; only reviewed. | Guide written and reviewed (docs/DEPLOYMENT.md). | Rehearse on a spare machine/VM, then fill in LINUX_DEPLOYMENT_TEST_RESULTS.md. |
| K3 | Medium | Data integrity | Atomic multi-document writes need a replica set. On a standalone server a crash between writes can leave partial data (reproduced: balance reduced, no payment). | Production refuses standalone unless `ALLOW_STANDALONE_MONGODB=true`; compensating rollbacks still cover thrown errors. | Run MongoDB as a (single-node) replica set or Atlas. |
| K4 | Medium | Rate limits | Limits are in memory, per process, and keyed by client IP. All staff of a school behind one public IP share the global budget (`RATE_LIMIT_MAX`, default 300 requests/min) — the e2e suite from one IP hit it (429, handled cleanly). | Clear 429 message in the apps. | Watch for 429s in logs during the pilot; raise `RATE_LIMIT_MAX` if a school is behind NAT. Shared store (Redis) before running several instances. |
| K5 | Medium | Messaging | External sends (SMS/WhatsApp/e-mail) are not covered by an outbox: a crash between "provider accepted" and "status saved" could lead to a duplicate on a manual retry. | Channels are off by default; statuses are honest (`not_configured`, `failed`). | Add an outbox/idempotency key per message before enabling paid channels at scale. |
| K6 | Medium | Recovery point | Backups are full, at most every `BACKUP_INTERVAL_HOURS`; no point-in-time recovery. Up to 24 h of changes can be lost with the daily schedule. | Encrypted, verified, downloadable backups. | Atlas continuous backup or oplog-based PITR if a shorter recovery point is required (BACKUP_RESTORE.md §8). |
| K7 | Medium | Backups | Automatic daily **download to the PC** is not built in (would need an agent holding platform credentials). | Manual download with checksum file; documented folder layout. | Decide whether you want a desktop sync agent; it is a separate component with its own risks. |
| K8 | Low | Backups | Snapshot backups must finish within MongoDB's snapshot window (300 s). Fine for school-sized data (staging: 1–2 s). | Fails visibly, never "completed". | For large data use `BACKUP_CONSISTENCY=freeze` at night. |
| K9 | Low | Accounts | Activation/reset links are given to the administrator, not delivered by e-mail/SMS; no self-service "forgot password". | Admins share links; platform can recover a school's Admin. | Add delivery once a channel is configured. |
| K10 | Low | Teacher scope | Teachers can read the list of classes, sections and subjects (no personal data). | — | Accept or restrict per school policy. |
| K11 | Low | Substitutes | Covers are by date (optional free-text periods), not specific timetable periods. | Keep covers short. | — |
| K12 | Low | Homework | One subject teacher per section-subject. | Use class teacher or split subjects. | — |
| K13 | Low | Dev tooling | 9 high advisories, all one issue: `braces` (GHSA-vfj7-8cjw-p6xm, stack exhaustion on deeply nested glob patterns) via `shadcn` CLI → fast-glob → micromatch → `braces@3.0.3`, and `eslint-config-next`. Dev dependencies only; `braces@3.0.3` is the latest release (no patched version); npm's only "fix" is a downgrade to `shadcn@1.0.0` / `eslint-config-next@14` (obsolete, breaking). Not in production bundles (`npm audit --omit=dev` = 0). Exploitable only by a developer feeding hostile glob patterns to the CLI. | — | Update when upstream publishes a fix. |
| K14 | Low | Dev environment | The development server (`npm run dev`, `NODE_ENV=development`) still syncs indexes automatically and **drops** indexes the models do not declare. The developer `.env` points at a MongoDB Atlas cluster. | Production never does this. | Never point `npm run dev` at a database with real data. |
| K15 | Info | Local files | `school-os-backend/.env.backup-before-ai` is an untracked copy of an older `.env` containing secrets. | Git-ignored, not committed. | Delete it once you no longer need it; rotate any secret that was ever shared. |
| K16 | Info | Not tested | Connection-pool exhaustion, slow-query injection, replica-set failover, network partitions, slow AI provider latency, 24 h scheduled backups, disk-full during backup, real Atlas. | Code paths reviewed / unit-tested where noted. | See DATABASE_FAILURE_TESTS.md and FINAL_STAGING_VERIFICATION.md. |
| K17 | Info | Performance | Figures are from one Windows machine (API, MongoDB and load generator together). One API process ≈ 140 req/s. | — | Re-measure on the home server before quoting capacity. |
