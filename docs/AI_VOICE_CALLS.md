# AI voice conversations (Stage 3)

An authorized school administrator configures a short conversation (purpose, questions, language) for **one parent**. The parent's phone rings through the normal app call (`docs/VOICE_CALLS.md`). When they answer, an AI assistant on the server:

1. says it is an automated AI assistant (not a person), for which school and staff member, and whether a transcript is kept;
2. asks for consent;
3. asks the configured questions, with short follow-ups;
4. records the answers;
5. says goodbye and hangs up.

Staff see the status, answers, summary, outcome and (if kept) the transcript on the website. There is no mass calling: campaigns are Stage 4.

Module: `src/modules/ai-calls`. Website: `/ai-calls`. Mobile: the normal call screen with an AI disclosure.

## How it works

```
website (leadership) ──POST /ai-calls──▶ checks: permission ai_calls:manage, plan calls.ai_voice,
                                         parent–student relationship, engines, limits
                                         └─ AiCallAgent ─▶ startAiCall: an ordinary call session (kind "ai")
parent's phone ◀── rings (call.incoming, ai: true) ──────┘
      answers ──▶ WebRTC (Opus) ◀──▶ server AI peer (werift, pure TypeScript)
                                      │ 20 ms Opus → 16 kHz PCM → voice activity detection → utterance
                                      │ speech-to-text (STT) → conversation engine → language model (no tools)
                                      │ text-to-speech (TTS) → Opus → back to the phone (barge-in stops it)
                                      └ answers / summary / outcome → AiConversation (MongoDB)
```

- **One agent per conversation.** It has its own call session, peer connection, codecs, buffers and timers. Signals are relayed only between that call's two bound connections. Concurrent AI calls cannot mix audio, transcripts or state, and ordinary calls are unaffected.
- **Fixed by code, never generated:** the disclosure, the consent question and its decision (yes/no words in Urdu, Roman Urdu and English, where "no" wins), and the closing lines.
- **Generated by the model:** only the wording of the configured questions and follow-ups, plus the extracted answers. The model returns strict JSON. Answers are accepted only if they fit the question (yes/no, number, date, one of the choices, short text); unknown keys are ignored.
- **The AI has no tools.** It cannot look up, change or promise anything. Requests about fees, attendance or records, complaints, or "let me talk to a person" set **follow-up requested** for staff. Answers are proposals that staff check; nothing in school data changes automatically.

## Configuration

Language model: the platform AI provider (`docs/AI_PROVIDERS.md`), through the existing usage tracking and monthly token limits (usage feature `voice_conversation`). A self-hosted model works with provider `custom` and an OpenAI-compatible endpoint (e.g. Ollama `http://host:11434/v1`).

| Variable | Default | |
|---|---|---|
| `AI_CALLS_ENABLED` | `true` | |
| `AI_CALL_STT_PROVIDER` | `none` | `openai_compatible`: `POST {URL}/audio/transcriptions` (multipart WAV, `model`, `language=ur`) |
| `AI_CALL_STT_URL`, `_MODEL`, `_API_KEY` | —, `whisper-large-v3`, — | e.g. a self-hosted faster-whisper server `http://stt-host:8000/v1` |
| `AI_CALL_TTS_PROVIDER` | `none` | `openai_compatible`: `POST {URL}/audio/speech` (WAV); `http_wav`: `POST {URL}` `{text, language, voice}` returning 16-bit PCM WAV |
| `AI_CALL_TTS_URL`, `_MODEL`, `_VOICE`, `_API_KEY` | | |
| `AI_CALL_PROVIDER_TIMEOUT_MS` | 20000 | per STT/TTS request |
| `AI_CALL_MAX_CONCURRENT` | 2 | AI calls at once on this instance (CPU, engine capacity) |
| `AI_CALL_MAX_CONCURRENT_PER_SCHOOL` | 1 | |
| `AI_CALL_DAILY_LIMIT_PER_SCHOOL` | 20 | |
| `AI_CALL_MAX_MINUTES` | 8 | hard length limit |
| `AI_CALL_MAX_TURNS` | 20 | |
| `AI_CALL_SILENCE_SECONDS` | 12 | asks again twice, then ends |
| `AI_CALL_TRANSCRIPT_RETENTION_DAYS` | 90 | transcripts are deleted after this; answers and summary stay |

Plan feature **`calls.ai_voice`** (category Calls) is in no default plan. It needs `calls.voice`, and is lost when a subscription is ineligible. The permission **`ai_calls:manage`** belongs to the owner, principal and office administrator; it cannot be given to custom roles. Keys and URLs stay on the server; the apps receive none of them.

`GET /ai-calls/availability` reports what is configured. Starting a call answers `503 AI_CALL_UNAVAILABLE` with `details.missing` (`speech_to_text`, `text_to_speech`, `language_model`) until all three are available. There is no fallback that pretends to talk.

## Choosing self-hosted engines for Urdu (not installed)

Nothing was downloaded or installed. The production server was **not inspected**: there was no access, by rule. Before choosing, run this on the server and share the output:

```bash
nproc; free -h; df -h /; lscpu | grep -E 'Model name|Flags' | head -2; nvidia-smi 2>/dev/null || echo "no NVIDIA GPU"; uptime
```

| Part | Self-hosted option | Urdu quality | Rough needs | Notes |
|---|---|---|---|---|
| STT | faster-whisper `large-v3` (CTranslate2), OpenAI-compatible server | Best open option for Urdu | GPU ≥ 6–10 GB VRAM for real time; CPU int8 on 8+ cores ≈ 1–3 s per short answer | `medium`/`small` are much worse on Urdu. Test with real parents' speech |
| STT | whisper.cpp server (`large-v3` q5) | Same model | CPU-only, 4–8 GB RAM; slower | |
| TTS | Meta MMS-TTS `urd-script_arabic` (VITS, ~150 MB) behind a small HTTP server (`http_wav`) | Intelligible, robotic | CPU is enough | Check the model's licence (CC-BY-NC) before commercial use |
| TTS | Hosted OpenAI-compatible TTS | Better voice | Paid per character | Optional only |
| LLM | Ollama (`qwen2.5:7b` or `llama3.1:8b`, Q4) as provider `custom` | Usable Urdu, imperfect | 6–8 GB RAM; on CPU 3–10 s per reply (too slow for natural turns) | A GPU or a hosted provider (e.g. the existing Groq option) gives 0.5–2 s |

A realistic low-cost setup is self-hosted STT and TTS on a machine with a modest GPU, with the language model either self-hosted on the same GPU or on an existing low-cost provider. CPU-only works for testing, but expect pauses of several seconds per turn. Always do a listening test in Urdu before using it with parents.

## Privacy, consent and records

- No audio is stored. Audio exists in memory for the current utterance only.
- **Before consent nothing is kept:** no transcript and no answers. A refusal or an unclear reply records only `consent: refused/unclear`. Not answering records only the call outcome.
- **The transcript is optional per call** (`storeTranscript`). It is kept only after consent, begins with the disclosure the parent heard, and is deleted after the retention period by an hourly job.
- Every record is scoped to the school, and to the staff member's campuses. Another school's ids answer 404.
- **Audit log:** `ai_call.started`, `ai_call.finished`, `ai_call.cancelled`, `ai_call.transcript_viewed` (whenever a transcript is opened), plus `call.started` for the underlying call.
- **Stored per conversation:** configuration, call id, status, consent, answers, summary, outcome, follow-up flag, failure reason, and usage (turns, seconds of speech, characters spoken, model tokens, duration).

## Failure handling

| Situation | Result |
|---|---|
| Parent's app not open, busy, declines, no answer | `not_answered` (reason given), no AI processing |
| No clear consent | goodbye, `no_consent` |
| STT/TTS server down or slow (`AI_CALL_PROVIDER_TIMEOUT_MS`) | apology if possible, hang up, `failed` (`stt_unavailable` / `tts_unavailable`) |
| Language model fails | next question asked as written; after 2 failures, apology and `failed` (`llm_unavailable`) |
| Silence | asks again twice, then goodbye |
| Time or turn limit | closing line, saved as far as it got |
| Staff press **Stop call** | hangs up at once, `cancelled` |
| Server restart | interrupted conversations are closed as `failed` (`server_restart`) at startup |

Limits are enforced per instance, and the concurrency reservation is atomic within one process. With several API instances the counters need shared storage (`docs/VOICE_CALLS.md`, "several instances").

Development creates them automatically. ## What is verified

- **Automated tests** (`tests/ai-calls.test.ts`): full conversations over a real WebRTC connection between the server's AI peer and a separate WebRTC client, with real Opus audio both ways, voice activity detection, consent, questions, answers, transcript, summary, audit, call history. Also no consent, not answered, transcript off and expiry, cancel, permissions, plan feature, tenant isolation, missing engines, concurrency limits, input validation, and engine unit tests.
- In those tests the speech engines and the language model are **test doubles**: scripted transcription, a tone instead of speech, scripted model replies.
- **Not verified:**
  - real Urdu speech recognition and synthesis (no engine runs here);
  - a real language model's Urdu quality;
  - the agent talking to a real phone (react-native-webrtc) and to browsers;
  - latency;
  - calls across networks (TURN).

  Until those are tested with real engines and real devices, AI calls are **implemented but not end-to-end verified**.
